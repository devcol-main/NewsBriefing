# 오너 컨펌 프로토콜 (Telegram / Slack 공용)

오너는 대부분 폰으로 확인한다. 메시지는 짧고, 한 번에 하나만 묻는다.

## 컨펌 요청 형식
```
[컨펌요청] <서브프로젝트> / <단계: 계획|결과물|게시>
요약: <2~3줄>
산출물: <파일 경로 또는 미리보기 3줄>
선택: 승인 / 수정: <내용> / 보류
```

## 오너 응답 처리
- `승인` → 다음 단계 진행
- `수정: ...` → 해당 내용 반영 후 다시 컨펌 요청
- `보류` → STATUS.md 에 보류 기록, 다른 태스크 진행
- `미션: ...` → 새 요청으로 보고 PM이 계획부터 시작

## 컨펌이 반드시 필요한 경우
- 작업 계획 확정
- 외부 게시·발송 (블로그, SNS, 이메일, 스토어 제출)
- 비용이 드는 작업 (유료 API 대량 호출 등)
- main 브랜치 머지 (예약 작업의 `briefings/` 직접 push는 제외 — CLAUDE.md 참고)

## 알림 전용 (컨펌 불필요)
- 매일 브리핑 완료, 렌더 완료, 에러 발생
